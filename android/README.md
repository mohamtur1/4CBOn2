# 4CBOn2 Android

Native Kotlin/Compose Android companion for the 4CBOn2 prototype.

## Current state

The source foundation was created in Build Division 04 and its first local navigation was added in Division 06. It contains one launcher activity, five visible local destinations (Home, Ask, Agents, Browser, Activity), truthful unavailable-state screens, and a Home-linked manual Kaggle competition handoff checkpointed in revised Division 09.

The Ask destination visibly reserves **Ask a Question** and **How do I? tutorial** entry points, but they are deliberately disabled until their real local/online capabilities are implemented and verified.

Division 11 adds a dependency-free, versioned local entity store (`LocalEntityDatabase`, `LocalAgentDraft`, and `LocalActionEvent`) with a synthetic file-backed close/reopen test. Division 12 adds a dependency-free, owner-selected capability registry (`SelectedApp`, `AppActionCapability`, `ActionRoute`, and `SelectedAppCapabilityRegistry`) with a narrow per-app probe boundary, fail-closed decisions, and manual-only enforcement for sensitive actions; it has no UI, no persistence, and no installed-app inventory. Division 13 adds a bounded per-job scope contract (`ScopeContract`, `ScopeTarget`, `ScopeLimits`, `CompletionMode`, and `ActionScopeEnforcer`) that refuses out-of-scope targets, excluded actions, unpermitted cloud transfer, expired jobs, and exhausted action budgets before any discovery; cloud transfer defaults to off. It also has no UI or persistence. Division 14 adds a local control lease (`ActionLease`, `BoundedJobController`) with owner-only resume, epoch-bound stale-command rejection, a terminal stop, and a fresh post-resume state check; cancellation is entirely on device and readies the owner Take Over/Pause/Stop controls. It has no UI wiring, persistence, or authentication claim. Division 15 adds `OfflineDraftRepository`, a bounded create/edit/list/load layer over the existing local entity database at unchanged schema version 1, with an explicit draft state machine, paired local events, and no reference to the registry, scope, or lease — so a saved draft never grants permission or starts a job. It has no UI wiring and no encryption. Division 16 adds `OwnerFileIntake`, a bounded owner-picked file model with an exact-match MIME allow-list, a 5 MiB cap applied to reported metadata, six explicit refusal reasons, and an export planner that produces a plan rather than content. It exposes no byte, stream, file, or path accessor at all (proved by a reflection test), requests no storage permission, walks no directories, and does not wire a platform picker yet. Division 17 adds `OfflineKnowledgeLibrary` and `LocalKnowledgeItem` for saving and searching local reports and evidence with recorded provenance (`OWNER_SUPPLIED`, `OWNER_OBSERVED`, `LOCAL_DRAFT_DERIVED` — never an invented service response or citation), and raises the local database to **schema version 2**, with version 1 files still readable and upgraded in place. It has no UI wiring, no encryption, and no network. Division 18 adds `LocalTableAnalysis`, one bounded pure function that summarises a small CSV or JSON table into exact per-column count/minimum/maximum/total, or refuses it with one of eleven named reasons in a fixed order — refusing over-cap or ambiguous tables rather than silently trimming rows. It holds no state, touches no database, registry, lease, or scope, and adds no persistence. Division 19 adds `PersistentWaitingQueue`, a local list of jobs the owner wants later that survives restart and raises the local database to **schema version 3** with versions 1 and 2 still readable. The queue has no executor, scheduler, or network client: recovery is derived by comparing a job's last owner action against the session start, so opening it can only report what is waiting. A recovered job requires an explicit owner acknowledgement, which records attention and performs no work. Division 20 adds `SensitiveActionApprovalGate`, the owner's approval for one sensitive act: bound to an exact destination identity with no prefix, substring, or case-folded match, a lifetime that never outlives the job scope, a small use count consumed atomically, and a deliberate single-tap confirmation that refuses wildcards, blanks, and stale stamps. It composes with `ScopeContract` rather than duplicating it — a refused scope can never be rescued by an approval — and approvals live only in memory so a restart invalidates them instead of honouring a stale permission. Division 21 adds `BoundedAppAction`, the first code that reaches an external effect: it dispatches **only** an `APP_INTENT` open of an owner-declared entry point, refuses share, transfer, and manual-handoff routes, and reports one of four honest outcomes — `Refused` (nothing attempted), `Completed`, `Failed`, or `Unknown` — where `Unknown` is never collapsed into success or failure and is never retried. The platform call sits behind an injectable `AppActionPort` whose only wired implementation refuses everything, so the shipped app cannot dispatch at all; real dispatch is untested. Neither division adds a credential, cloud sync, service response, or broad telemetry, and all use synthetic local data only. The app does **not** yet contain working question answers, tutorial plans, active agents, local knowledge-library UI, active service connections, phone-control permissions, accessibility service, screen capture, general browser automation, user credentials, or an updated retained APK for the current source state. The active source suite now has 228 tests (198 preserved plus 30 bounded-action tests); the no-artifact CI workflow supplies compilation and build verification because this workspace currently has no local JDK/Gradle/Android SDK toolchain. See `LOCAL_DATABASE.md`, `SELECTED_APP_CAPABILITIES.md`, `SCOPE_CONTRACT.md`, `TAKEOVER_LEASE.md`, `OFFLINE_DRAFTS.md`, `FILE_HANDOFF.md`, `KNOWLEDGE_LIBRARY.md`, `LOCAL_ANALYSIS.md`, `WAITING_QUEUE.md`, `SENSITIVE_APPROVAL.md`, and `APP_ACTION.md`.

The active Kaggle API client, token entry, token slot, and OAuth route have been removed. The manual Kaggle screen validates one competition URL and requests an external Android handler—an installed app or browser—only after an explicit owner tap. During 09c the installed Kaggle app opened the correct page before sign-in; the owner then signed in personally and performed Cancel/Back. No credential was shared, and no competition join or submission occurred. Browser-specific and unreported subchecks remain unverified. The Android Keystore boundary remains only for the separately scoped future GitHub credential route and is unpopulated. GitHub public metadata/root listing was previously visible from the build environment. A fixed, manual-handoff-only Colab notebook reference also exists; its target notebook was not publicly found. See `KAGGLE_MANUAL_COMPETITION_HANDOFF.md`, `CREDENTIAL_STORAGE.md`, `GITHUB_READ_ACCESS.md`, and `COLAB_ENTRY_ROUTE.md`.

## Baseline

- Application ID: `io.github.mohamtur1.fourcbon2`
- Minimum SDK: 26
- Compile SDK: 37 (required by the selected stable Compose/AndroidX set)
- Target SDK: 36 (pending separate runtime-behavior testing)
- JDK: 17
- Android Gradle Plugin: 9.2.0
- Gradle Wrapper: 9.4.1
- Kotlin Gradle Plugin: 2.2.10

Use `./gradlew :app:assembleDebug` after provisioning a compatible local Android SDK/JDK. `local.properties`, SDK/toolchain directories, secrets, and generated build output are intentionally ignored.

See the root `android/` design and build-status documents for scope and current verified status.
