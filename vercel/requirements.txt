# 4CBON2 — Vercel serverless dependencies (trimmed for the 500 MB function-size limit)
#
# Vercel's Python runtime bundles EVERY installed package into each serverless
# function, whether or not the code imports it. The full dependency set must
# therefore stay under Vercel's 500 MB hard cap per function.
#
# HOW TO MEASURE — use tools/measure_bundle.py, not `du -sh`:
#   python3 -m venv /tmp/m && /tmp/m/bin/pip install -r vercel/requirements.txt
#   python3 tools/measure_bundle.py /tmp/m/lib/python3.11/site-packages
# A fresh install is ~540 MB on disk but only ~402 MB of that ships: ~112 MB is
# __pycache__ bytecode and ~26 MB is tests/, neither of which reaches a lambda.
# Counting them overstates the bundle by ~35% and produces a false "over budget"
# alarm. Current: ~402 MB shipped -> ~423 MB in Vercel's accounting, ~77 MB of
# margin. Last verified 2026-09-12, including a live boot of app.py + api/*.
#
# Removed on 2026-09-10 (measured site-packages 589.9 MB -> 400.3 MB exact bytes,
# i.e. ~566 -> ~420 MB in Vercel's block accounting; Vercel build projected
# ~567.42 MB -> ~421 MB against its reported 500 MB cap):
#   chromadb==0.5.23        — never imported by vercel/ runtime code; its
#                             transitive tree (onnxruntime, kubernetes, tokenizers,
#                             grpcio, opentelemetry, chroma-hnswlib, ...) alone was
#                             ~190 MB. Nothing in app.py / api/*.py references it.
#   PyPDF2==3.0.1           — never imported by vercel/ runtime code.
#   python-docx==1.1.2      — never imported (also pulled in 11 MB lxml).
#   beautifulsoup4==4.12.3  — never imported by vercel/ runtime code.
#
# NOTE: google-api-python-client (~100 MB, bundled as `googleapiclient`) is a hard
# dependency of google-generativeai 0.8.x and cannot be removed while we pin the
# classic SDK that app.py imports (`import google.generativeai as genai`).
# Do NOT re-add heavy packages here without re-measuring the bundle size.
#
# huggingface-hub is pinned explicitly: gradio 4.44 only declares
# `huggingface-hub>=0.19.3` (no upper bound), and gradio 4.44 imports
# `HfFolder`, which was removed in huggingface-hub 1.0. Without this pin a fresh
# resolve installs huggingface-hub 1.x and `import gradio` crashes at cold start.
# (0.36.2 is the last 0.x release; chromadb's `tokenizers<1.0` used to cap this
# transitively — that cap disappeared when chromadb was removed.)

fastapi==0.115.0
uvicorn==0.30.6
gradio==4.44.0
google-generativeai==0.8.3
supabase==2.7.4
python-multipart==0.0.9
pydantic==2.9.2
requests==2.32.3
huggingface-hub==0.36.2

# cryptography is pinned explicitly because gate_core.py imports it directly to
# verify Supabase session tokens against the project's JWKS (the project moved
# from a shared HS256 secret to ECC P-256 / ES256 signing keys).
# It costs NOTHING extra: it already arrives transitively via
# google-generativeai -> google-auth, which requires cryptography>=38. Verified
# by installing this file into a clean venv — cryptography is present at 16 MB
# whether or not this line exists. Declaring it anyway follows the same rule as
# the huggingface-hub pin above: a direct import must not depend on a transitive
# resolution that a future google-auth release could drop.
# Pinned exactly, like everything else in this file. 50.0.1 is what resolves
# today and satisfies google-auth's cryptography>=38.0.3.
cryptography==50.0.1

# ── Heavy transitive floaters, pinned for reproducibility ──────────
# gradio 4.44 pulls these in and they are the largest items in the bundle after
# googleapiclient. Left unpinned, a rebuild can resolve different versions and
# move the bundle size between deploys, which makes the 500 MB budget
# unauditable. Pinning them makes the build deterministic.
#
# These are NOT the newest releases — they are the newest that satisfy
# gradio 4.44's own constraints (pandas<3.0, pillow<11.0, numpy<3.0,
# matplotlib~=3.0). Pinning pandas==3.0.5 or pillow==12.3.0, which are current,
# would make the resolve fail outright. Verified 2026-09-12 by installing this
# file into a clean venv and booting the app.
#
# Re-measure after changing any of these:
#   python3 -m venv /tmp/m && /tmp/m/bin/pip install -r vercel/requirements.txt
#   python3 tools/measure_bundle.py /tmp/m/lib/python3.11/site-packages
# The measurement MUST exclude __pycache__: compiled bytecode is ~112 MB of a
# ~540 MB install and is not shipped in a Vercel function.
numpy==2.4.6
pandas==2.3.3
matplotlib==3.11.2
fonttools==4.65.0
contourpy==1.3.3
kiwisolver==1.5.1
pillow==10.4.0
